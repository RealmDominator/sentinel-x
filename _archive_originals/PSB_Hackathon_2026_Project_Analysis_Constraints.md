# 2. Participant Profile Assumptions (IMPORTANT)

All future project analysis, architecture decisions, implementation plans, roadmaps, and recommendations should assume the following participant profile:

## Team Structure

- Team Size: 1 Person (Solo Participant)
- No additional developers available
- No dedicated cybersecurity expert
- No dedicated AI/ML expert
- No dedicated DevOps engineer
- No dedicated UI/UX designer

## Educational Background

- Generic Engineering Student
- Completed First Year of Engineering in India
- Beginner-level software development experience
- Limited real-world project experience

## Cybersecurity Knowledge

Assume:

- Basic understanding of cybersecurity concepts
- Limited malware analysis knowledge
- Limited reverse engineering knowledge
- No professional SOC experience
- No advanced threat intelligence experience
- No practical banking cybersecurity experience

## AI/ML Knowledge

Assume:

- Beginner-level AI understanding
- Beginner-level ML understanding
- Limited knowledge of model training
- Limited experience with LLM integration
- Limited experience with MLOps

## Development Environment

Project development planning should assume:

- VS Code as primary IDE
- AI-assisted development
- Use of AI coding assistants
- Extensive usage of LLMs during development
- Rapid prototyping approach
- Preference for open-source tools

Examples:

- ChatGPT
- Claude
- Gemini
- GitHub Copilot
- Cursor
- Continue.dev
- Other VS Code AI extensions

# 3. Official Problem Statements

## Problem Statement 1

### Harnessing Generative AI for Automated Reverse Engineering, Static and Dynamic Analysis, and Risk Scoring of Fraudulent Mobile Applications (APKs) and Malwares.

Expected focus areas:

- APK analysis
- Malware analysis
- Static analysis
- Dynamic analysis
- Reverse engineering
- Threat classification
- Risk scoring
- Explainable AI-generated reports
- Automated analyst assistance

---

## Problem Statement 2

### Developing a solution having AI/ML capabilities for detecting suspicious transactions and mule accounts by ingesting financial transactions and/or fraud monitoring solution alerts and/or transaction monitoring system alerts and government cyber fraud alerts/tickets and preventing circulation of fraudulent proceeds through mule accounts.

The solution should consume:

- Real-time regulatory inputs
- Regulatory feeds
- Fraud monitoring alerts
- Transaction monitoring alerts
- Government cyber fraud alerts
- Cross-channel banking data

Expected focus areas:

- Fraud detection
- Mule account detection
- Transaction intelligence
- Real-time risk scoring
- Graph/network analysis
- AI-assisted fraud investigations
- Alert prioritization

# 13. Project Analysis Constraints

Any future project analysis should optimize for:

## Primary Goal

Maximize:

- Shortlisting probability
- Prototype completion probability
- Final presentation quality

## Secondary Goal

Maximize:

- Innovation
- Practicality
- Real-world banking relevance
- Deployment feasibility

## Constraints

Avoid solutions requiring:

- Large cybersecurity teams
- Large ML teams
- Massive datasets
- Enterprise infrastructure
- Complex MLOps pipelines
- Multi-year R&D efforts

- AI-assisted development
- Modular architecture
- Incremental implementation
